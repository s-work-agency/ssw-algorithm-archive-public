# 알고리즘이라는 것

<!-- site-only-skip-end -->

알고리즘을 두고 오래 해왔던 생각을 짧게 정리한 내용입니다.

## 1. 이론이기 전에 활용의 방법입니다

저는 알고리즘을 **컴퓨터를 어떻게 활용할 것인가에 대한 방법**이라고 생각해 왔습니다. 이름이
붙고 증명이 따라오다 보니 이론처럼 보이지만, 하려는 일은 처음부터 하나였습니다. 가진 기계로
원하는 답을 얻는 길을 찾는 것입니다.

그래서 처음 보는 알고리즘을 볼 때 구현하기에 앞서 보는 것이 있습니다. **무엇을 아끼려고 이렇게
하는가**입니다. 어떤 것은 시간을 아끼려고 메모리를 더 쓰고, 어떤 것은 메모리를 아끼려고 같은
계산을 다시 합니다. 그 교환이 눈에 들어오고 나면 이름과 증명은 그다음에 붙습니다.

## 2. 구현보다 자원과 상황을 먼저 봤습니다

코드를 빠르게 치고 구현을 정확하게 하는 일도 중요합니다. 다만 제가 더 중요하게 본 쪽은
따로 있었습니다. **이 알고리즘이 컴퓨터 자원을 어떻게 쓰는가**, 그리고 **실제로 어떤 경우에
어떻게 써야 효율적인가**입니다.

같은 정렬이라도 입력이 이미 거의 정렬돼 있는지, 값의 폭이 좁은지, 메모리를 얼마나 더 내줄 수
있는지에 따라 답이 달라집니다. 구현을 아무리 잘해도 고른 것이 상황과 맞지 않으면, 그 정확한
구현은 느린 답을 정확하게 내놓습니다.

## 3. AI가 구현을 맡으면서 안목이 더 중요해졌습니다

이제 구현은 AI가 꽤 잘해 줍니다. 그러면서 무게중심이 옮겨 갔다고 생각합니다. **언제 어떤
알고리즘을 쓸지 고르는 안목**이 전보다 훨씬 더 중요해졌습니다.

써 내는 일이 싸지면 고르는 일이 비싸집니다. 잘못 고른 자리는 더 빠르게, 더 정확하게 잘못
채워집니다. 무엇을 쓸지 정하는 판단은 여전히 사람이 들고 있어야 하고, 그 판단의 재료는
알고리즘이 자원을 어떻게 쓰고 어디서부터 맞지 않게 되는지에 대한 이해입니다.

## 4. 시나리오도 AI가 썼습니다

각 알고리즘의 시나리오 500종은 AI가 썼습니다. 지금 읽고 계신 이 글도 그렇습니다. 감출
이유가 없습니다.

더 솔직하게 적으면, 500종을 전부 읽고 검수하지는 못했습니다. 이 사이트에 공개된 몫은 조금
더 신경을 썼지만, 비공개의 500종은 어느 정도의 검수 기준을 두고 집필 세션과 검수 세션을
따로 돌려 자율에 맡겼습니다. 다만 제가 직접 읽은 몫에서 얻은 것이 있었습니다. 안다고 생각했던 알고리즘도 어떤 입력부터 맞지 않게 되는지, 그때는 무엇으로
갈아타야 하는지를 문장으로 읽고서야 정리된 것들이 있습니다. 저는 그렇게 얻은 것에 가치가
있다고 생각합니다.

텍스트를 사람이 쳤는지 AI가 쳤는지가 얼마나 중요한지는 경우에 따라 다릅니다. 다만 뜻을
전하거나 미처 보지 못한 대목을 짚어 주는 영역이라면, 평균으로 보면 사람이 쓴 쪽보다 낫다고
저는 생각합니다. 검수하며 읽은 글들에서 본 것이 그랬습니다.

여기까지 적은 생각이 아카이브의 모양을 정했습니다. 500종 전부에 **언제 쓰고 언제부터는 쓰지
않는가**를 적은 사용 시나리오를 붙인 것도, 모델에게 코드를 새로 써 내라고 하는 대신 검증된
것 중에서 **고르라고** 한 것도 전부 여기서 나왔습니다. 그 이야기는
[소개](../README.md)에 있습니다.
